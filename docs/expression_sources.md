# Baseline single-cell expression: dataset review and integration plan

## Recommendation

The first baseline import now uses **Robertson et al. (2026), well-watered controls only**: 36,455 annotated nuclei, three replicates, 14 original cell-type labels, 33,438 available processed-matrix features and 32,017 exact RAP-locus matches. The source matrices are summarized without loading the full Seurat object; cell labels are extracted separately. See [implementation and validation](baseline_expression.md).

Wang's separately deposited normal-root subset is now the second import (see [Wang implementation](wang_expression.md)). The full eight-organ atlas remains a broad-organ candidate, but its main R object is approximately 5.1 GB on disk and may need substantially more RAM to load. A small control-only metadata export and sparse matrices would make Robertson easier on the current 8 GB Mac. Do not reduce to marker genes to work around memory limits.

## Data model

Keep publication, dataset, sample and original cell-group identifiers separate. Proposed tables:

| Table              | Required content                                                                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| expression_dataset | Stable dataset ID, publication DOI, repository/accession, file checksums, organism/cultivar, assay, original reference/annotation, normalization definition, retained-feature coverage |
| expression_sample  | Dataset/sample ID, original sample name, organ, stage, genotype, treatment and explicit baseline eligibility reason                                                                    |
| expression_feature | Dataset/original feature ID, mapped RAP ID if unambiguous, mapping resource/version, mapping status; retain unmapped and ambiguous features                                            |
| expression_group   | Dataset, organ, stage, original cell-type label, original cluster ID, original annotation source; retain replicate context                                                             |
| expression_summary | Dataset, sample/group, original feature, cell count, expressing-cell count, fraction expressing, mean expression, metric/normalization label                                           |

Use raw counts greater than zero for detection where available: percentage = 100 × expressing cells / eligible cells in that group. Compute mean expression over **all** eligible cells, including zeros, using a stated nonnegative RNA normalization. An initial reproducible metric can be mean(log1p(10,000 × counts / per-cell RNA library size)); record which feature set defines library size. If authors supply an equivalent documented unscaled RNA assay it may be retained as its own metric. Do not calculate detection from integrated, batch-corrected or scaled values, or treat negative residuals as counts.

Never aggregate across studies. Preserve sample-level summaries and show replicate counts; any pooled within-study summary must state its weighting. Rank cell types for a gene within a compatible dataset/organ-stage context, using the same expression metric and eligibility rule, with tied ranks where appropriate. There is no cross-study numeric ranking. Nuclear and whole-cell assays differ, as do stage, genotype and sampling depth.

## Import acceptance checks

1. Check checksums, sparse matrix dimensions, unique feature IDs and unique sample-plus-barcode keys. Validate every retained cell against the original annotation metadata; report unmatched and duplicate joins rather than dropping silently.
2. Enumerate all samples, explicitly allow baseline wild-type/normal controls and exclude every stress or mutant sample. Keep organ and developmental stage visible.
3. Audit feature coverage before selecting variable genes. Include every available mapped feature, not only markers or highly variable features. Record missing/filtered/not-measured separately from measured zero detection.
4. Map IDs through versioned resources; retain original IDs and ambiguity. Do not transfer coordinates between different references using a name-only match. Do not double-count transcript or many-to-one mappings.
5. Compare a small set of gene/group summaries against an independent calculation, including a zero-detection gene and a gene not present in the matrix. Verify percentages lie in [0,100] and that group counts match metadata.
6. Publish only compact summaries to the web database. Add a gene-search expression endpoint and within-study dot plots after these checks pass.

## Display plan

Show one study panel at a time, or separate clearly labelled panels. Dot **area** represents percentage of expressing cells, with a size legend; a perceptually ordered, color-blind-accessible sequential scale represents expression within that panel. Include numeric values in an accessible table, cell counts, organ, stage, assay, metric and publication links. Use explicit “not available” for absent features rather than a zero-sized dot.

Allow users to select neighboring genes from the existing GWAS explorer and display them as columns against cell types in the same study. If relative color scaling is used separately for each gene, label it clearly and keep absolute within-study summary values in the table; it must not imply equal expression levels between genes or studies. No differential-expression, stress comparison, enrichment, or causal inference is part of this stage.
