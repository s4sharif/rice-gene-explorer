# Li et al. (2023): diploid pistil expression with curated annotations

## What is implemented

RiceLENS now includes a third experimental paper: [Li et al., Developmental Cell (2023)](https://doi.org/10.1016/j.devcel.2023.03.004). The import combines the original public GEO count matrices with cell annotations from [scPlantDB](https://biobigdata.nju.edu.cn/scplantdb/), dataset SRP386976. The curation resource explicitly identifies PMID 37028425, BioProject PRJNA859914, Nipponbare pistils, normal conditions, and three experiments. Cite both the experimental paper and [scPlantDB, He et al.](https://doi.org/10.1093/nar/gkad706).

**This is a curated-label integration, not an exact reproduction of the authors' final annotated atlas.** The authors' public [repository](https://github.com/yuhaolab/snrnaseq/tree/917c586379fee80477fd93b6436b25d5ff242c08) supplies counts and processing code, but the inspected repository does not include the final barcode-to-cell-type table or annotated objects generated by that code. RiceLENS does not rerun clustering to invent those labels.

The website identifies the dataset as **Li et al. (2023) · scPlantDB-curated** and displays a source note with links to both publications. It is kept separate from Wang and Robertson.

## Source and sample selection

| Original GEO sample | SRA experiment / curated Orig.ident | Library                    | Included nuclei |
| ------------------- | ----------------------------------- | -------------------------- | --------------: |
| GSM6346349          | SRX16335164                         | Diploid pistil replicate 1 |           5,688 |
| GSM6346350          | SRX16335165                         | Diploid pistil replicate 2 |           4,081 |
| GSM6346351          | SRX16335166                         | Haploid pistil library     |        Excluded |

GEO describes wild-type Nipponbare pistils at heading stage, grown in normal climate-chamber conditions, aligned to IRGSP1.0. scPlantDB describes the stage as one day before flowering. Both descriptions are preserved in provenance rather than treated as an independently verified exact age.

The imported subset contains **9,769 nuclei**, **11 original curated annotation groups**, and **35,797 exact matches** to supported RiceLENS RAP genes. All **38,726 features** from the original GEO matrices are retained in the processing database; unsupported, noncoding or organellar identifiers are not guessed into a RAP locus. These are available reference-matrix features, not a claim that every feature is detected.

Original labels such as `S-Ovule`, `CT-Ovule` and `Inner ovary wall/Outer integument` remain unchanged. Compound labels are not resolved into more specific identities. The source `Unknow` and `Stamen residue` labels are excluded from the baseline pistil display, with counts retained in the exclusion audit.

## Exact joins and exclusions

The curated object contains 11,443 nuclei. The following non-overlapping exclusions account for the complete source partition:

| Reason                                                                       | Nuclei |
| ---------------------------------------------------------------------------- | -----: |
| Haploid 1N library, excluded rather than pooled as another diploid replicate |  1,003 |
| Source label `Stamen residue`                                                |    222 |
| Source label `Unknow`                                                        |    447 |
| Remaining labelled diploid barcode absent from the original GEO matrix       |      2 |
| Included                                                                     |  9,769 |

There are three absent barcodes before label filtering; one is already counted under `Unknow`, leaving two additional unmatched labelled nuclei. Their original IDs and labels are recorded in `data/expression_li_join_validation.json`. No approximate barcode matching is used. The exact `SRX...@@_` source prefix is removed only after confirming the experiment-to-GEO mapping from the original sample record. Duplicate sample/barcode pairs cause failure.

The original diploid matrices contain 15,016 nuclei in total. Nuclei without an eligible matched curated label are not used in cell-type expression summaries. Consequently, these results describe this intersection subset, not all original counts or the exact cell population reported in the paper. The nuclei were enriched by ploidy sorting; the sample composition does not estimate natural cell-type proportions.

## Metrics and validation

Detection is an original GEO RNA count greater than zero. Mean expression is mean(log1p(10,000 × count / per-nucleus library size)), including zero-count nuclei. Library sizes use every feature in the original matrix. Replicate summaries are retained, and the combined display uses nuclei-weighted means within this dataset. Numeric values are not compared across studies, and no stress, differential-expression or causal analysis is performed.

The website supports ranked expression, detection percentages, neighboring-gene dot plots, numeric tables and CSV export. Missing features remain distinct from measured zero detection. The export preserves source feature IDs, mapping status, experimental publication and the metric definition.

`prepare_li.py` validates metadata and produces an exact, audited cell partition. `scripts/summarize_li.R` processes sparse original matrices. The independent Python validator rereads the original matrices to check cell counts, detection and normalized expression. Unit tests cover the matching/exclusion logic and ensure separate studies are not pooled.

## Reproduction

```sh
python3 fetch_expression.py --study li
python3 scripts/extract_rds_metadata.py data/raw/li/SRP386976.rds.gz data/raw/li/cell_metadata.tsv --gzip-layers 2
python3 prepare_li.py
Rscript scripts/summarize_li.R
python3 build_expression.py --study li
python3 validate_expression.py --study li
```

The curated object is gzip-compressed twice. A streaming metadata reader avoids loading its assay matrices into RAM. The count matrices come directly from GEO, so the curated object's normalized/scaled values are never used to calculate expression. Inputs and checksums are pinned in `data/expression_li_inputs.json`; the selection policy is in `data/expression_li_selection.json`. Raw inputs and local SQLite files are excluded from Git.

The main outputs are `data/expression_li.sqlite`, `data/expression_li_manifest.json`, `data/expression_li_validation.json`, the cell-join audit, and local per-sample summaries under `data/raw/li`.

Observed validation: all **88** independent gene–replicate–annotation-group checks passed (four genes × two diploid samples × eleven groups), as did all **20** software tests.
